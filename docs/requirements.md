# 雑談シミュレーションツール 要件定義書

- 最終更新: 2026-07-05
- 関連文書: [調査レポート](./research.md) — 本書の設計判断の根拠。確度ラベル([A]検証済み/[B]引用取得済み/[C]スニペット/[G]一般知識)は調査レポート側で定義

## 1. 背景・目的

### 1.1 解決したい問題

雑談が苦手な人の多くは、性格の問題ではなく**会話パターンのストック不足**でつまずいている。

- 何を聞けばいいか(話題の引き出し)が頭にない
- 相手の返答に対して次の一手が浮かばず、沈黙になる
- 特に「初対面」「面識はあるが気を遣う相手」との会話、アイスブレイクの場面で消耗する

一般的な会話術の本や記事は「オウム返しをしよう」「共通点を探そう」といった原則は教えてくれるが、**実際の会話の流れの中でどの一手を選ぶか**は練習しないと身につかない。かといって実際の会話は失敗のコストが高く、練習の場にならない。

### 1.2 解決アプローチ

**分岐選択式の会話シミュレーション**で、失敗しても安全な環境で雑談のパターンを反復練習できるツールを作る。

- 「木戸に立てかけし衣食住」の定番テーマから会話をスタート
- 質問候補の提示 → プレイヤーが選択 → 相手の返答 → 次の一手候補、の分岐をたどる
- 訓練するのは個別のセリフの暗記ではなく、**「相手の返答タイプを認識して、適切な次の一手を選ぶ」というメタスキル**。これはテーマを問わず汎化する
- 位置づけはSST(ソーシャルスキルトレーニング)のロールプレイ訓練の自習版。SSTは40年以上の実績があり、熟練トレーナー不足でアクセスが限られていることが自動化・セルフサーブ化の動機とされる(調査レポート§3)。**学習ツールであり、医療・治療・診断は範囲外**
- 「分岐選択式でソフトスキルを教える」形式自体には、分岐ナラティブ型アプリ eQuoo の大規模RCTで高い継続実績が報告されており(調査レポート§5.4)、コンセプトの先行事例がある

### 1.3 ターゲットユーザー

- 雑談に「パターンが欲しい」と感じている社会人・学生
- 想定利用: 通勤時間や会話イベントの前などに1回1〜3分の練習を反復
- 将来的にはスマホで実会話直前・最中の「伴走」利用も視野に入れる

## 2. スコープ

### 2.1 v1(ローカルPC版)に含むもの

| 機能 | 概要 |
|---|---|
| 練習モード | 相手の返答を重み付きランダムで分岐させるシミュレーション |
| ふりかえり | セッション後に各選択の解説と別ルートを確認 |
| ツリー閲覧 | 会話ツリー全体と解説を眺めて予習・復習 |
| パターン図鑑 | 出会ったフレーズ・技法のコレクション |
| 今日の1本 | 日替わりの推奨シナリオ |
| 履歴 | ローカル保存のプレイ記録 |

### 2.2 将来スコープ(v1では作らないが、設計で妨げない)

- **リアルタイム伴走モード**: 相手が実際に言った返答に一番近い分岐を手動タップして次の一手候補を見る。**練習モードと同じ会話ツリーを使い回す**(v1のデータ設計で対応可能にしておく)。スマホ化のタイミングで追加
- **フリー会話モード**: LLM(Claude API等)で相手役を動的生成。ハイブリッド方針の将来拡張
- **スマホアプリ化**: レスポンシブ → PWA → 必要なら Capacitor 等でストア配布
- 間隔反復(苦手カテゴリの再出題)、ストリーク等の追加ゲーミフィケーション

### 2.3 明確にやらないこと

- 音声認識・音声合成(v1では文字のみ)
- ユーザー登録・サーバーサイド(データは全てローカル)
- 医療・カウンセリング領域への言及

## 3. コア概念

### 3.1 会話エンジン方針: ハイブリッド

- **アプリ本体は静的な会話ツリー(JSON)のみで動作**する。オフライン動作、API費用ゼロ、品質が安定
- コンテンツの増産には LLM をバッチ利用する(生成 → スキーマ検証 → 人の監修 → 取り込み)。§8 参照
- ランタイム LLM は将来のフリー会話モードまで導入しない

### 3.2 テーマ(topic)

「木戸に立てかけし衣食住」= 気候・道楽(趣味)・ニュース・旅・天気・家族・健康・仕事・衣・食・住。

v1 では汎用性の高い **4テーマに絞って深く**作る:

1. **天気・季節**(き+て を統合)— 最も安全な入口
2. **道楽(趣味・休日の過ごし方)** — 話が広がりやすい本命
3. **食** — 誰でも語れて地雷が少ない
4. **衣(ファッション・持ち物)** — 「褒める」起点の練習に最適

テーマの追加はコンテンツ(JSON)の追加だけで済む設計にする(§7)。全11テーマの場面別適合度・地雷は**付録A**に整理済み。

### 3.3 場面(scene)

相手の個別ペルソナは持たず、**場面パラメータに集約**する:

| ID | 場面 | 例 |
|---|---|---|
| `first_formal` | 初対面・フォーマル | 仕事の顔合わせ、取引先との待ち時間 |
| `first_casual` | 初対面・カジュアル | 友人の紹介、イベント、飲み会 |
| `senior_known` | 顔見知りの目上・気を遣う相手 | 別部署の上司、義家族、習い事の先生 |

場面は選択肢の適切さを変える(例: 初対面で家族の話は踏み込みすぎ)。場面×話題の適合マトリクスは**付録A**として本書末尾に定義した(根拠: 調査レポート§1)。

### 3.4 返答カテゴリ(response category)— 分岐設計の要

相手の返答を具体的な発話ではなく**有限個の「型」で分岐**させることで、パターンの組合せ爆発を防ぐ。v1 は4カテゴリ:

| ID | カテゴリ | 例(ファッションを褒めた場合) | 求められる次の一手 |
|---|---|---|---|
| `expand` | 肯定して広がる | 「ありがとうございます、実はお気に入りで…」 | 掘り下げ質問で乗る |
| `counter` | 質問返し・褒め返し | 「〇〇さんの時計も素敵ですね」 | 短く受けて自己開示 or 返す |
| `short` | 短く終わる | 「ああ、どうも」 | 角度を変えてもう一手 or 話題転換 |
| `flat` | そっけない・興味なし | 「…どうも」(乗ってこない) | 深追いせず撤退・話題転換 |

- **この分類は会話分析の知見で裏取り済み**(調査レポート§4、敵対的検証済みクレーム多数): 会話は隣接ペア(質問→応答)という有限のペア型の連鎖として記述でき、応答は preferred(即座・直接)/ dispreferred(遅延・緩和・言い訳付き)という構造的に異なる有限カテゴリに分類できる。「具体発話でなくカテゴリで分岐」は恣意的な簡略化ではなく、会話の実構造に沿った抽象化である
- 4カテゴリと会話分析の対応: `expand`=preferred な応答+追加情報(一問二答型)、`counter`=応答+新たな質問の開始、`short`=整列するが最小限の応答、`flat`=dispreferred/non-answer 寄り
- **weight の初期値校正**: 実会話コーパスでは質問への non-answer は約15%(調査レポート§4.2)。`flat` の出現重みはデフォルト1〜2割を目安にする
- ユーザーが例示した「褒めたら相手が『お気に入りなんです』と肯定するルート/褒め返してくるルート」はそれぞれ `expand` / `counter` に対応する
- カテゴリごとの対処はテーマ横断で共通性が高いため、**訓練効果が汎化し、コンテンツも部分的に共用できる**
- 「良い一手」の判定原理は会話の**前進性(progressivity)**: 会話を気持ちよく前進させる手が best、前進を止める手(尋問・腰折り・踏み込みすぎ)が ng(調査レポート§4.2)

### 3.5 1セッションの構造

実時間30秒〜1分の雑談に相当する:

```
オープナー選択(1手) → 相手の返答 → 応答選択 ×2〜4往復 → クロージング選択(1手) → 終了
```

- この構造は雑談の標準モデル「①声をかける→②話す→③別れる」(齋藤孝、30秒を雑談の基本単位とする)と整合する(調査レポート§2.1)
- **全ての終端は「きれいな切り上げ」で終わる。** 「雑談が上手い人=サクッと終わらせられる人」であり(調査レポート§2.1)、終わらせ方は必須の練習対象。会話分析でも「閉じの連鎖」は独立した構造単位である(§4.1)
- シミュレーションの目的は「面白いことを言う」ではなく「**会話のパスを回し続けて気持ちよく終わる**」ことだとUI上でも明示する(結論・オチ不要という雑談の設計思想)
- NG選択肢を選んだ場合は即終了ではなく「気まずい空気」を演出した上で**リカバリの選択肢**を提示する(失敗からの立て直しも練習ポイント)

## 4. 機能要件

機能全体は SST の標準サイクル「教示 → モデリング → リハーサル → フィードバック → 般化」に対応づけて設計する(調査レポート§3.1):

| SSTサイクル | 対応する機能 |
|---|---|
| 教示 | シナリオ冒頭の1行ガイド(この場面で何を練習するか) |
| モデリング | F4 ツリー閲覧(best ルートを手本として眺める) |
| リハーサル | F2 シミュレーション |
| フィードバック | F3 ふりかえり |
| 般化 | ふりかえり末尾の「今日どこかで試す一手」提示(実会話チェックインは将来) |

### F1. シナリオ選択

- 場面(3種)× テーマ(4種)からシナリオを選ぶ。シナリオ = 1本の会話ツリー
- トップに「今日の1本」(日付から決定論的に選ぶ日替わり推奨)を表示
- 各シナリオに状況説明(例: 「友人の紹介で初めて会った同年代の人と席が隣になった」)

### F2. シミュレーション画面(中核)

1. 状況説明と相手の様子(例: 「相手は個性的なスニーカーを履いている」)を表示
2. プレイヤーの選択肢を **2〜4個** 提示(1つはNG/微妙な選択肢が混ざることがある)
3. 選択すると、相手の返答が**重み付きランダム**で選ばれたカテゴリの発話として表示される
4. 次の選択肢が提示される。3〜5往復でクロージングに到達して終了
5. ターン進行のインジケータを表示
6. 選択肢の文字量は一目で読める長さ(目安全角30字以内)。解説はこの画面では出さない(テンポ優先。即時表示のON/OFF設定は許容)

### F3. ふりかえり画面(セッション終了後)

- たどったルートをターンごとに再掲し、各選択の品質(best / ok / ng)と**理由の解説**を表示。「自分のロールプレイを見返すことが改善点の理解を深める」というSST研究の知見の実装(調査レポート§3.2)
- **フィードバックの比率は「ポジティブ2:改善1」を目安**にする(自動SST研究のユーザー評価で最も好まれた比率 [検証済み]。調査レポート§3.2)。ng選択が多いセッションでも、まず良かった選択を2つ挙げてから改善点を示す
- そのターンで**選ばなかった選択肢と別の返答カテゴリの分岐**も開いて確認できる
- 使った技法(オウム返し、感想+質問 等)のタグを表示し、図鑑への収集を通知
- 末尾に「今日どこかで試す一手」として、このセッションで登場した best フレーズを1つ提示する(般化の促し)

### F4. ツリー閲覧モード

- シナリオの会話ツリー全体をツリー表示で俯瞰し、任意のノードの発話・解説を読める
- 目的: プレイ前の予習、プレイ後の「他のルートはどうなっていたか」の確認

### F5. パターン図鑑

- プレイ中に出会った/選んだフレーズと技法をコレクションとして蓄積
- 技法タグ(例: オウム返し、感想+質問、5W1H、切り上げ)で絞り込み表示
- 収集率の表示(継続動機)

### F6. 履歴

- プレイ日時、シナリオ、たどったルート、選択品質の内訳をローカル保存(localStorage)
- 直近の履歴一覧と簡単な傾向(例: 「`flat` への対処で ng が多い」)を表示

## 5. コンテンツ要件

### 5.1 規模の見積り

- 1ツリー = 深さ3〜5往復、各選択ポイント2〜4択、相手返答は4カテゴリ(場面により2〜4カテゴリに省略可)
- ナイーブに全展開すると爆発するため、**ノードの合流**を積極的に使う(例: どの流れでも `counter`(褒め返し)への対処は共通ノードに合流できる)
- 概算: 1ツリーあたり発話スニペット40〜60個
- **MVP: 4テーマ × 2場面(first_casual, senior_known)= 8ツリー ≈ 400スニペット**
- v1: 3場面に拡張して12ツリー。以降は LLM 増産パイプライン(§8)で拡張

### 5.2 各ツリーの必須要件

- [ ] 全終端がクロージング(きれいな切り上げ)で終わる
- [ ] 4返答カテゴリのうち3つ以上が登場する(`flat` への撤退練習を必ず含む)
- [ ] NG/微妙選択肢が1ツリーに2箇所以上あり、それぞれ理由の解説とリカバリ分岐を持つ
- [ ] 全選択肢に `quality`(best/ok/ng)と `explanation` が付いている
- [ ] 場面パラメータに整合している(初対面ツリーに踏み込みすぎの best 選択肢がない等)
- [ ] 掘り下げ技法のタグが選択肢に付与されている

**NG選択肢は次の5類型から作る**(調査レポート§1.5。ランダムに「変なセリフ」を作らない):

| 類型 | 例 |
|---|---|
| ① 曖昧質問 | 「休みはどうでした?」(何を答えればいいか不明で負担) |
| ② プレッシャー質問 | 「趣味はあるんですか?」(“ちゃんとした趣味”の圧) |
| ③ 話の腰を折る質問 | 話の目的から逸れた横やり(「なんで有楽町? 横浜のほうが近くない?」) |
| ④ 踏み込みすぎ | 値段・年収・家族構成など距離感を誤る質問 |
| ⑤ タブー直撃 | 政治・宗教・ひいき球団・収入・容姿・学歴(付録A) |

解説文も類型ごとにテンプレート化でき、「なぜまずいか+使い回せる原則」を安定して書ける。

### 5.3 文体ガイドライン

- 選択肢: 全角30字以内、話し言葉、敬体は場面に合わせる(`first_formal`/`senior_known` は敬語)
- 相手の発話: 1〜2文。カテゴリの性格が伝わる長さ(expand は長め、flat は極端に短く)
- **カテゴリごとの書き分けは会話分析の観察に従う**(調査レポート§4.2): `expand` は即座・直接+追加情報(一問二答型)、`flat`/`short` は間・最小化・「うーん、どうですかね…」のような言い訳・緩和の目印を付ける。こうするとプレイヤーが現実の会話でも返答タイプを認識しやすくなる
- 解説: 2〜3文。「なぜ良い/まずいか」+「使い回せる原則」をセットで書く

## 6. データスキーマ(JSON ドラフト)

コンテンツは `content/scenarios/*.json`。エンジンとコンテンツを完全分離し、テーマ追加=ファイル追加にする。

```jsonc
{
  "id": "fashion-first_casual-01",
  "topic": "衣",                        // 天気季節 | 道楽 | 食 | 衣 (拡張可)
  "scene": "first_casual",             // first_formal | first_casual | senior_known
  "title": "初対面の集まりで相手の持ち物を褒める",
  "situation": "友人の紹介で初めて会った同年代の人と席が隣になった。相手は個性的なデザインのスニーカーを履いている。",
  "entry": "n1",
  "nodes": {
    "n1": {
      "type": "player_choice",
      "choices": [
        {
          "text": "そのスニーカー、いい色ですね。どこで見つけたんですか?",
          "quality": "best",
          "techniques": ["褒め+オープン質問"],
          "explanation": "具体物への言及+入手経路の質問は答えやすく、話が広がりやすい。",
          "next": "n2"
        },
        {
          "text": "それ、おいくらでした?",
          "quality": "ng",
          "techniques": [],
          "explanation": "初対面で値段に踏み込むのは距離感を誤りやすい。",
          "next": "n2ng"                 // 気まずい空気 → リカバリ分岐へ
        }
      ]
    },
    "n2": {
      "type": "partner_response",
      "branches": [
        { "category": "expand",  "weight": 4,
          "text": "ありがとうございます、実はお気に入りで。先月旅行先でたまたま見つけて。",
          "next": "n3a" },
        { "category": "counter", "weight": 3,
          "text": "ありがとうございます。〇〇さんのその時計も素敵ですね。",
          "next": "n3b" },
        { "category": "short",   "weight": 2,
          "text": "ああ、ありがとうございます。",
          "next": "n3c" },
        { "category": "flat",    "weight": 1,
          "text": "……どうも。",
          "next": "n3d" }
      ]
    },
    "n9_close": {
      "type": "player_choice",
      "closing": true,
      "choices": [ /* きれいな切り上げの選択肢群 */ ]
    }
  }
}
```

設計上のポイント:

- `partner_response.branches[].category` は §3.4 の4カテゴリの enum。**伴走モード(将来)ではこの branches をユーザーが手動タップする**だけなので、同じデータで両モードに対応できる
- `weight` により練習モードの出現率を制御(場面ごとに現実的な分布に)
- 複数の `choices[].next` が同一ノードを指してよい(合流によるスニペット圧縮)
- スキーマは JSON Schema として `content/schema.json` に定義し、CI 相当のスクリプトで検証する(§8.2)

## 7. アーキテクチャ・技術スタック

### 7.1 構成方針

- **静的SPA**: ビルド成果物は静的ファイルのみ。ローカルでは `npm run dev`、配布はビルド済みファイルを開くだけでも動く
- **エンジン(UI+状態遷移)とコンテンツ(JSON)の完全分離**
- 保存は localStorage(履歴・図鑑・設定)。外部送信なし

### 7.2 スタック(推奨)

| 層 | 選定 | 理由 |
|---|---|---|
| ビルド/フレームワーク | Vite + React + TypeScript | エコシステム、将来の Capacitor 化実績、型でコンテンツスキーマを守れる |
| 状態管理 | useReducer or zustand | この規模に十分 |
| スタイル | Tailwind CSS | スマホ化を見据えたレスポンシブを低コストで |
| テスト | vitest | コンテンツ整合性チェックを自動テスト化 |
| ツリー表示(F4) | 軽量な自前実装 or 小規模ライブラリ | 依存を増やしすぎない |

### 7.3 スマホ化へのパス

1. v1: レスポンシブ対応の SPA(選択肢はタップ前提の大きなボタン)
2. PWA 化(manifest + service worker)でホーム画面追加・オフライン
3. 必要になったら Capacitor でストア配布(コードはほぼ流用)

## 8. コンテンツ増産パイプライン(LLMバッチ利用)

「パターンを永遠に人手で作り続けるのは無理」への答え。**アプリ本体とは独立した開発時ツール**(`tools/generate/`)として用意する。

### 8.1 生成

- テーマ・場面・使用技法・NG選択肢の数などの制約を与えたプロンプトテンプレートで、Claude API にツリー JSON を生成させる(開発者が手元で実行するスクリプト)

### 8.2 検証(自動)

- JSON Schema 検証(構造・enum・文字数制限)
- 整合性チェック: `next` の参照先が存在する / `entry` から全ノードに到達可能 / 全終端が `closing` / カテゴリの網羅要件(§5.2)を満たす
- このチェッカーは人手コンテンツにも常時かける(vitest に組み込み)

### 8.3 監修(人)

- 生成物は `content/drafts/` に置き、人がレビュー・修正して `content/scenarios/` に昇格させたものだけがアプリに載る
- レビュー観点チェックリスト(§5.2 + 文体ガイドライン §5.3)を README に添付

## 9. 継続利用の仕組み

### 9.1 設計原則(調査レポート§5 の結論)

調査の結果、「Duolingo 的な仕組みの直輸入」は本ツールの対象ユーザーには不適切と判断した:

1. **内発的動機を優先する。** ゲーミフィケーション一般の効果量は小さく(g=0.25〜0.49)、動機づけ・行動面の効果は方法論の厳密な研究では不安定。メンタルヘルス隣接アプリのメタ分析ではゲーミフィケーションは効果にもアドヒアランスにも有意に寄与していない。派手なポイント・バッジ・ランキングは入れない
2. **利用量を成功指標にしない。** 「Engagement–Efficacy Gap」(利用量増が成果改善に結びつかない)が指摘されている。北極星は「起動回数」ではなく**「実会話で試せた」(般化)**に置く
3. **罪悪感を煽らない。** 説得的デザインは操作・心理的苦痛の害を生みうる。特に本ツールのユーザー層(会話への苦手意識)には、ストリーク切れの罰的演出・責める文言・煽り通知を**禁止事項**とする
4. **習慣の足場としては「同じ文脈での短い反復」が本筋。** 「毎日決まったタイミングで1〜3分」という利用形態そのものが習慣形成研究に合致する。仕掛けよりもセッションの短さ・起動の速さが効く
5. **もしストリーク系を入れるなら寛容設計**(休んでも途切れない救済、切れても中立的な文言)。厳格ルールより「ゆるみ」を許す方が動機づけに有効

### 9.2 段階別の実装

| 段階 | 仕組み | 説明 |
|---|---|---|
| v1 | 今日の1本 | 日替わり推奨シナリオ。起動→1プレイ→終了の1〜3分習慣の足場 |
| v1 | パターン図鑑 | フレーズ・技法の収集率表示。進歩の可視化(内発的動機=有能感の支援) |
| v1 | 履歴と傾向 | 「`flat` への対処が苦手」等の気づきを返す |
| v1 | 般化プロンプト | ふりかえり末尾の「今日どこかで試す一手」(F3) |
| v1.1 | 苦手の再出題(間隔反復) | ng が多い返答カテゴリ/技法を優先的に「今日の1本」へ。間隔反復のスケジューリング改善だけで練習継続+9.5%の実績があり(Duolingo研究)、最優先の拡張候補 |
| v1.1 | 練習記録の控えめな表示 | 連続日数ではなく「今週◯回練習した」型の累積表示を第一候補とする(損失回避に依存しない) |
| スマホ化 | 控えめなデイリーリマインダー | リマインダーはゲーミフィケーションより継続への寄与の根拠がある |
| スマホ化 | 実会話チェックイン | 「今日どれか試せた?」の記録。成功指標の本丸 |

## 付録A: 場面×話題の適合マトリクスとテーマ別素材

コンテンツ制作(§5)の入力。調査レポート§1のソース(確度B/C中心)から統合した**設計判断であり、監修時に見直してよい**。

### A.1 適合マトリクス

◎=安全で推奨 / ○=使えるが聞き方に注意 / △=相手から出たら乗る(自分からは振らない) / ×=避ける

| テーマ | 初対面フォーマル | 初対面カジュアル | 顔見知りの目上 | 備考 |
|---|---|---|---|---|
| 天気・季節 | ◎ | ◎ | ◎ | 最安全圏。「外の話」はプライベートに踏み込まない |
| 道楽(趣味) | ○ | ◎ | ○ | 「趣味は?」でなく「最近ハマってるものは?」で聞く(§5.2 類型②回避) |
| ニュース | ○ | ○ | ○ | 明るい時事のみ。政治・事件・災害は避ける |
| 旅 | ○ | ◎ | ○ | 連休前後は特に自然 |
| 家族 | × | △ | △ | 初対面から自分では振らない。相手が出したら乗る |
| 健康 | △ | △ | △ | 自分の軽い話(花粉症等)は○、相手の健康への質問は避ける |
| 仕事 | ○ | △ | △ | フォーマルでは文脈上自然。カジュアルで職業を聞くのは踏み込み。目上には愚痴・評価に注意 |
| 衣(ファッション・持ち物) | ○ | ◎ | ○ | 褒め起点に最適。値段を聞くのはNG(類型④) |
| 食 | ◎ | ◎ | ◎ | 「好きな食べ物」「この近くの店」は目上にも鉄板 |
| 住 | △ | ○ | △ | 「ご出身は?」は定番だが、住所の特定に向かう質問は避ける |

**タブー(全場面共通)**: 政治・宗教・ひいき球団(「政宗の皿」= 政治・宗教・野球・サラリー)+ 年収/お金・容姿・学歴・家族構成。NG選択肢(類型⑤)の材料としてのみ登場させる。

### A.2 v1 対象4テーマのオープナー例(制作の種)

- **天気・季節**: 「桜、咲いてきましたね」「花粉、今年ひどくないですか?」
- **道楽**: 「最近なにかハマってるものあります?」「休みの日はアクティブ派ですか? インドア派ですか?」
- **食**: 「この近くでおいしい店あるって聞いたんですけど、行かれたことあります?」「お昼ってどの辺で食べてます?」
- **衣**: 「そのスニーカー、いい色ですね。どこで見つけたんですか?」「今日のネクタイ素敵ですね」

### A.3 切り上げフレーズ例(全ツリーの終端素材)

- 「それでは、また」「じゃあ、またぜひ」+ 一言の感想(「お話できてよかったです」)
- 時間・行動を理由にする型: 「そろそろ行きますね」「お引き止めしちゃってすみません」
- 次につなげる型(顔見知り向け): 「今度その店、教えてください」
